# 系统构成 
* MCU：核心控制器，ARM Cortex-M架构 ESP32-S3芯片
    * 主频：运算速度，如72MHz、480MHz
    * 内核位数：8位、32位、64位，cpu一次性运算的数据宽度
* 存储器Flash/SRAM：存储代码片段和运行数据
    * Flash：存储程序代码（固件），掉电不丢失
    * SRAM：运行时的数据存储（变量、栈堆等）
* 传感器：温湿度、光照、姿态等等
* 外设：GPIO、UART、SPI、ADC（模拟转数字）等
    * ADC：模拟信号转为数字值，如电压、电流
    * DAC：数字信号转模拟信号，如音频
    * PWM：通过占空比控制输出电压平均值，用于电机调速、LED调光，占空比=高电平时间/PWM周期，所以占空比越大，平均电压越大，速度越快或者亮度越高
* 通信模块：WiFI、BLE、LoRa、CAN等

# 驱动开发与外设编程
* 总线架构
    * AHB：高级高性能总线连接高速外设，系统顶级主干总线，等同于系统时钟，CPU内核，片内Flash，RAM，DMA，以太网，USB需要大数据流的模块
    * APB：高级外设总线，AHB的二级外设分支总线，分频降频运行，APB1最高36MHz，APB2最高72MHz，外设接口，低速外设寄存器，只读写配置，无连续大数据
* 通用外设驱动
    * GPIO
    * 配置模式：
        * 输入：浮空、上拉、下拉、模拟（ADC）
        * 输出：推挽（可以输出高低电平）、开漏（只有接GND的下拉，上拉需接外部电阻）
        * 复用模式 
* 面试问题
    * HAL与LL库的选择：
        * 快速开发选择HAL，性能敏感选择LL
        * HAL：主打易用性和代码可移植性，开发效率高，代码体积大，执行速度相对慢
        * LL：追求代码效率和执行性能，更接近硬件底层，代码提交小，执行效率高
    * I2C通信中ACK/NACK的作用
        * ACK（应答，低电平）：接收方正确接收到数据，发送低电平
        * NACK（非应答，高电平）：接收方无法继续接收，发送高电平
        * SDA默认位高电平，即空闲状态，发送数据时拉低SDA，在ACK/NACK第九个时钟脉冲，SDA线控制器转    移，接收方接管如果数据正常则拉低，否则位高电平
        * DMA和CPU直接传输的优缺点：释放CPU资源，提高传输效率，但是需要配置DMA，增加代码复杂度

# 实时操作系统（RTOS）
* 特点：抢占内核，高优先级任务先执行，低优先级任务后执行。
* 常见RTOS：FreeRTOS、RT-Thread
* 优缺点：
    * 优：实时性高，任吗 务切换快，资源管理好
    * 缺：开发复杂，学习成本高，代码体积大
* 线程间通信
    * 队列：用于存储数据，线程间通过队列传递数据，传递数据使用
        * 线程安全：队列操作需要加锁，确保线程安全，避免数据不一致
        * 支持阻塞读写
    * 信号量：用于同步线程，线程间通过信号量协调工作，同步/互斥使用
        * 用于任务同步，中断与任务通信
    * 事件：用于通知线程事件发生，线程间通过事件通知工作，多事件通知使用
